### U-01 · 依赖成熟度尽调
- 原文：「新增依赖前先确认社区成熟度与维护活跃度，优先选择成熟度、活跃度高的库。」
- 作用：把"引入依赖"从"能解决问题"升级为"值得长期承担"——防住选到停更、无人维护的库。
- 是否推荐：✅ 推荐（非 no-op：模型默认按"能跑通"选包，不查维护状态；可判"是否给出成熟度依据"）
- 使用场景：`base`（边界：需求确需外部能力且无平台原生方案时才进入本条；与之配套的最小化条款见 P-13/P-14 的合并句）
- 通用化改法：新增依赖前先评估其维护活跃度与社区成熟度，优先选择长期维护、被广泛使用的库；在提交信息或变更说明里给出一行依据。→ **最终句**：`新增依赖前先评估其维护活跃度与社区成熟度，优先选择长期维护、被广泛使用的库。`
- 重复：包含或张力（→ 裁决：与 `A1.26`（成熟依赖净减少代码才引入）互补不重复——`A1.26` 管"该不该引入"，本条管"在可选方案里挑哪个"；两条同列，先准入后选型）

### U-02 · 按版本核对官方文档
- 原文：「安装后按版本查询官方最新文档核对 API 与配置项，不要照抄旧教程或自身记忆。」
- 作用：防住"凭记忆或旧教程写出的 API/配置"——版本漂移是最高频的静默错误来源。
- 是否推荐：✅ 推荐（非 no-op：模型倾向复用训练记忆里的旧写法；可判"是否引用了与版本匹配的文档依据"）
- 使用场景：`base`（边界：仅在依据版本敏感时适用——引入新依赖、升级依赖、调用外部接口；`A1.05` 管的"文档不人工复述机器可读清单"与本条互补）
- 通用化改法：`新增或升级外部依赖后，按所装版本查官方文档核对 API 与配置项，不依据旧教程或记忆下笔。`
- 重复：无重复

### U-03 · 配置只写非默认项
- 原文：「写配置前先确认该配置项是否必需、工具默认值是否已经满足需求，只声明与默认值不同的部分。」
- 作用：防住"处处显式声明默认值"——配置膨胀会掩盖真正的差异项，并在工具默认值变更时产生静默偏差。
- 是否推荐：✅ 推荐（非 no-op：模型写配置时倾向把能想到的键都写上；可判"每条声明能否说出与默认值的差异"）
- 使用场景：`base`（边界：安全与合规要求显式声明的项除外——这类属 `A1.28` 的"保持写死"一侧）
- 通用化改法：`只声明与工具默认值不同的配置项；写前先确认该键必需且默认值不满足需求。`
- 重复：包含或张力（→ 裁决：`A2.08`（"可配置本身不是理由"）管**新增可配置能力**，本条管**配置文件里写什么**；两条是同一原则在"设计与落地"两侧，保留两条并在 §4 注明同一出处）

### U-04 · 相信类型、不做冗余防御
- 原文：「相信类型：类型系统已经保证的情况不再写运行时防御代码，不做多余的空值兜底、不重复校验参数、不用 try/catch 吞掉异常。」
- 作用：砍掉没有信息量的防御代码；同时把"不吞异常"钉住，避免用防御掩盖真实错误。
- 是否推荐：✅ 推荐（非 no-op：冗余防御是模型的高频产出；可判"每处运行时校验能否指出它防的真实边界"）
- 使用场景：`base`
- 通用化改法：`只在真正的信任边界做运行期校验；类型已保证的取值不再重复校验或兜底；捕获到的异常要么处理要么向上抛出，不静默吞掉。`
- 重复：**同义（→ 并入 A1.31）**。"只在真正的信任边界做运行期校验，进程内已由类型保证的取值不重复校验"已由 A1.31 承载；本次把 U-04 的两个新子句（**不吞异常**、**不做空值兜底**）补进 A1.31 的最终句，两个来源合并为一条，不新增语句。
- **写入动作**：A1.31 最终句改为上面"通用化改法"的文本（编辑器/写入者按此替换）。

### U-05 · 一次性逻辑不提取工具函数
- 原文：「不为一次性逻辑提取全局工具函数，只有被两个以上模块复用且语义稳定的才提取。」
- 作用：防住"为单点逻辑造全局助手"——比单实现的抽象更难删。
- 是否推荐：✅ 推荐（非 no-op：抽工具函数是模型的默认动作；可判"每个工具函数能说出 ≥2 个调用模块"）
- 使用场景：`base`（边界：与 `P-11`（优先复用已有实现）配套——先找现成，再决定是否提取新的）
- 通用化改法：`只有被两个以上模块复用且语义稳定的逻辑才提取为共享函数；一次性逻辑就地保留。`
- 重复：**同义（→ 并入 R11）**。R11 已给"抽象至少两个使用点，否则内联"的通用判据；本条补"语义稳定"这一维。**写入动作**：R11 最终句改为 `每个抽象至少有两个使用点且语义稳定；只有一个使用点或语义未定时直接内联实现。`

### U-06 · 第三方边界收窄但不掩盖错误
- 原文：「第三方边界允许做必要的类型收窄，但不要用 `as` 掩盖真实的类型错误。」
- 作用：给出"哪里可以让步、哪里不许"的边界——外部数据需要收窄，但不能用断言把类型错误压下去。
- 是否推荐：✅ 推荐（非 no-op：用断言消错是模型的常见捷径；可判"每处断言能否说明为何验证充分"）
- 使用场景：`base`
- 通用化改法：`第三方边界可以做必要的类型收窄，但不用断言掩盖真实的类型错误；断言只减不增。`
- 重复：**同义（→ 并入 A1.32）**。A1.32 已管"不新增向未知类型的断言、已有断言只减不增"；本条补"第三方边界允许必要收窄"的许可面。**写入动作**：A1.32 最终句改为 `不新增向未知类型的断言；第三方边界可以做必要的类型收窄，但不用断言掩盖真实的类型错误；已有断言只减不增并保持基线。`

### U-07 · 不写多余类型标注
- 原文：「不写多余的显式类型标注或泛型参数，让 TypeScript 自己推断。」
- 作用：减少与实现重复的标注——它们会与推断结果漂移，且掩盖真实类型。
- 是否推荐：✅ 推荐（非 no-op：模型倾向把类型写全；可判"该标注是否与推断结果重复"）
- 使用场景：`base`（边界：公开 API 边界与推断不成立处仍需显式标注，见下句）
- 通用化改法：**去掉语言名**（"TypeScript"是专名，规则里不出现）：`不写多余的显式类型标注或泛型参数，交给类型推断；只在推断不成立或构成公开契约处显式标注。`
- 重复：无重复（池内 0 条相关）

### U-08 · 页面组件就近
- 原文：「页面组件就近写在对应路由文件里，只有被多处复用的 UI 才提取为公共组件。」
- 作用：把"组件的默认位置"钉在路由旁——就近能减少跳转与假复用。
- 是否推荐：✅ 推荐（非 no-op：模型倾向先把组件放进公共目录；可判"每个公共组件的调用点数"）
- 使用场景：`frontend`（边界：跨路由复用的界面元素才升级为公共组件）
- 通用化改法：`页面组件就近写在对应路由文件中；同一界面元素被多处复用时才提取为公共组件。`
- 重复：包含或张力（→ 裁决：后半是 R11（≥2 使用点）在界面层的实例，保留在本条以保持"就近"与"提取门槛"同句可读；两处判据同源，写入时在溯源映射里登记，不视为重复）

### U-09 · 界面交互层豁免测试用例
- 原文：R-07 裁决的补充落定 ——「跟 UI 交互界面相关的一律不考虑测试用例，由开发者自行验证」（用户第 5 轮）。
- 作用：把"界面层不做测试要求"这一政策写进规则集（此前只以"删除两条要求"的形式存在，读者看不到政策本身）；同时解除 `A2.03`（"用户可见的能力必须有测试"）与它的冲突。
- 是否推荐：✅ 推荐（这是用户的取舍决定，不是模型行为判据；作用是限定其它验证条款的适用范围）
- 使用场景：`frontend`（边界：只豁免界面交互层；非界面的用户可见能力——命令行输出、接口返回——仍按 `gates.md` 要求装配级测试）
- 通用化改法：``界面交互层的改动由开发者自行验证，不强制测试用例；界面以外的验证要求见 `gates.md`。``
- 重复：无重复（本条是适用范围限定，非新规范；与 `A2.03` 的关系是"给它加界面豁免"，见下）
