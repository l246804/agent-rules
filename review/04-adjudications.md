## 一、规则集的定位与形态

### R-01 档位机制（P-02/P-04/P-05/P-06/P-09）
- 两难：可开关的强度档（照做 / 强制最小实现 / 先质疑需求）增加表达力，也增加机制与记忆负担。
- **建议**：不设档位机制。保留一条默认强度（最小实现 + 命中即停），另加一条通用出口"用户明确要求更激进或更保守时按其要求执行"。
- 理由：规则集是写进项目指令文件的文本，不是产品；口令与档位会随会话丢失，且"质疑需求的强度"用一条条件式规则即可表达。

### R-02 一致性校验体系是否通用化（P-57…P-60、P-63）
- 两难：把"规则副本逐字一致 + 不变量 canary"做成通用要求，每个项目都得建 CI；不做，多入口分发就会漂移。
- **建议**：降级为**条件推荐**——"当仓库已有校验设施（CI/脚本入口）时，把可机器判定的规则一致性纳入其中"；不要求新建设施。
- 理由：规则集不该给轻量项目附加基建成本；有设施时它收益极高（唯一能防规则分叉的机械手段）。

### R-03 留痕体系（P-40…P-45；DSH A1.03/A1.40/A2.53）
- 两难：三种台账（持久化结构变更、决策理由、简化上限）机制同构、门槛不同；统一模板清晰，各自门槛贴合场景。
- **建议**：合并为一章，通用层只留**"有意简化必须留痕"**（一行注释写明天花板与升级路径，零设施成本）；"决策记录 / 变更致谢"列为条件推荐（多包或多人协作时）。
- 理由：注释级留痕是零成本的通用项；RFC 式记录的成本只在协作场景才回本。

### R-04 产品级 agent 约束（C 层，DSH C1–C5）是否纳入
- 两难：C 层（指令加载上限、沙箱分档与审批、格式版本、可见即可重建）是这套规则集里唯一"产品如何约束 agent"的面，纳入则显著加厚。
- **建议**：**单独一章**（`runtime-agent`），不进通用层；在文件顶部写明"只有当你在构建会运行 agent 的产品时才读本章"。
- 理由：语义层次不同——通用层教 agent 怎么干活，C 层是产品对 agent 的运行时约束；混在一起会稀释通用层力度。

### R-05 本地钩子（DSH B3）
- 两难：把明显错误挡在提交前收益早，但钩子可绕过、需要安装步骤。
- **建议**：条件推荐——"仓库已有钩子设施时，把格式/空白/生成物一致性放进 pre-commit"；不新建钩子体系，也不把它当唯一门禁。
- 理由：早失败收益真实，但"假安全感"风险要求它与 CI 分层，而非互相替代。

### R-06 按文件满额覆盖率（DSH B5）
- 两难：把未覆盖行当"可疑代码"信号，代价是逐条维护豁免清单。
- **建议**：不进通用层；写成"可选：对核心包启用按文件满额覆盖率"。
- 理由：属团队承受力问题，非普适纪律；规则集里只保留"没有检查的改动不算完成"。

### R-07 可见面与真实入口的验收强度（DSH A1.42/A2.60/A2.72/A3.25；含 A2.38 秒级内环例外）
- 两难：可见输出要端到端期望、测试只从真实入口启动、界面改动附真实录制——强度最高的组合落地成本也最高；A1.12 又禁止重复已通过的检查。
- **建议**：合并成两条条件式：
  1. "改动可见面（用户能看到的输出/界面）时，用端到端证据验证，测试从真实入口与出厂装配启动"——**有可见面即要求**；
  2. "成本低到可当类型检查用的检查可以反复跑（单文件、秒级、无外部依赖）；其余不重复已通过的检查"。
- 理由：把"是否要求"绑定到"是否有可见面"这一可判定条件，避免"有设施才要求"的模糊表述。

## 二、表达与判据口径

### R-08 负向条款的去留（P-19/P-22/P-23/P-28/P-30；K 的 11 条负向句）
- 两难：作为失败样例对弱模型有效，但纯禁止句不可判定、且把被禁行为拉进上下文。
- **建议**：一律改写成**正面可判句式**后保留（例："每个抽象至少有两个使用点，只有一个时直接内联"）；给不出正面目标的（人格句、不可判定的元注释）删除。
- 理由：可判定性是规则的门槛；正面表述同时解决触发强度与噪声。

### R-09 no-op 的判定口径（K 需裁决 5：R11 ↔ P-19）
- 两难：同一类规则（不为单次使用造抽象）在两份台账里判了相反的推荐。
- **建议**：定为**口径 D1**："no-op 判定必须有默认行为的依据；来源或公开观察已记录该失败模式常见时，判条件推荐而非不推荐。"
- 据此裁决：保留 R11 的可计数判据（抽象 ≥ 2 个使用点）；P-19 的宽泛版不复活（已折入 P-21）。
- 理由：no-op 检验是"是否改变行为 vs 默认"，而模型的过度抽象是来源明确记录的常见失败——判它 no-op 不成立。

### R-10 输出篇幅（P-27 ↔ P-29）
- 两难："至多三行说明"与"用户点名的解释给全"互相拉扯，硬数字会误伤。
- **建议**：去掉硬数字，写成"代码优先；不写未被请求的解释；被点名的解释给全；跳过的部分用一行说明"。
- 理由：判据可判（有无未请求解释、是否跳过了该说的），且不引入会漂移的额度。

### R-11 R13 的取舍（"不为不可能场景写错误处理"）
- 两难：保留会丢"被类型或契约排除的状态不必防御"的真实信号；照原样保留又诱导删掉本该留的防御。
- **建议**：保留但改写为"只为真实可能的状态写错误处理；被类型或调用契约排除的分支不写"，作为信任边界规则的配套。
- 理由：与 R-09 的口径一致——它对应的是可观察的过度防御，可判。

### R-12 R32 的定位（"规则偏保守；平凡任务自行判断"）
- 两难：作头部免责声明可防规则被过度执行，但它不可判定，且与"命中即停/不停工"拉扯。
- **建议**：不列入规则正文。
- 理由：不可判定 + 与其他条目张力；其防滥用意图已由"平凡任务按常识执行"的语气出现在出口条款里，无需单列。

### R-13 多步任务是否先给计划（K 需裁决 6：R30 ↔ P-27）
- 两难：先给计划提高可验证性，也可能变成噪声与拖延。
- **建议**：条件式——"任务有多个独立步骤或有实质风险时，先给简短计划（步骤 + 每步验证方式）；单步任务直接做"。
- 理由：绑定到"多步/有风险"这一可判定条件，避免一刀切。

## 三、行为取舍

### R-14 不确定时问还是先做（K 需裁决 1：R4/R5/R6/R7 ↔ P-24/P-17）
- 两难：不确定就问更安全但会停工；先交付最小版更快但可能做错方向。
- **建议**：条件化——"目标或方向不确定：先问一句再动手；细节不确定：按写明的假设交付最小版本"。
- 理由：两家的规则各自成立在不同维度；条件是"不确定什么"，可判定且不冲突。

### R-15 死代码默认值（K 需裁决 3：R21 ↔ P-21）
- 两难：默认不删安全但积累腐烂；默认删除干净但可能误删。
- **建议**：分工——"请求之外的既有死代码：只报告不删；自己改动造成的孤儿导入/变量/函数：必须清干净"。
- 理由：以"是否本次改动造成的"划界，两边都保住，且可判。

### R-16 依赖 vs 自研（DSH A1.26 ↔ P-14/P-16）
- 两难：P 默认"几行能做就不加依赖"，DSH 默认"能净删掉自有代码与测试就用成熟依赖"。
- **建议**：条件式——"引入成熟依赖能净删除更多自有代码与测试时优先引入；否则几行能做的功能不新增依赖"；把"净删除"作参考判据而非硬门槛。
- 理由：两条判据都成立，区别只在"净删除"是否被证明；条件化后不再互斥。

### R-17 接口变更的改动范围（DSH A1.02 ↔ K R18/R24）
- 两难：接口变更要同步更新所有消费者（完整性），K 要求改动不越界（手术式）。
- **建议**："因本次变更而失效的消费者更新，算请求内；与变更无关的相邻代码不动。"
- 理由：用"是否因变更而失效"划界，把"越界"从形式判断改为因果判断。

### R-18 单一真源 vs 逐字副本（DSH A1.54 ↔ P-52）
- 两难：多入口只留链接最干净，但某些宿主不跟随链接。
- **建议**：默认单一真源（指针/链接）；宿主不支持时允许逐字副本，且副本必须由脚本逐字校验一致。
- 理由：与 R-02 的一致性体系配套——允许副本的前提是"漂移会变红"。

### R-19 读端遇到未知必需记录：拒绝还是兼容（DSH A1.20 + C4）
- 两难：fail-closed 会挡住旧数据，静默跳过会重建出错误状态。
- **建议**：默认 fail-closed（拒绝加载并报错）；兼容只通过显式版本化迁移提供。
- 理由：静默跳过产生的是"看起来成功的错误状态"，代价高于一次显式报错。

### R-20 护栏是否进通用层（P-35 无障碍、P-36 硬件校准等）
- 两难：全进通用层稀释"最小实现"的力度；不进则特定项目缺护栏。
- **建议**：通用层只留"安全与数据不可损"红线（含凭据与不可信输入）；无障碍、硬件校准等归对应场景文件或条件式。
- 理由：护栏的性质是"不可商量"，而它与场景绑定；分层比堆在通用层更可判。

### R-21 用户的完整实现要求 vs 质疑（P-24/P-37、K R6）——已定，仅记录
- 现状：三条台账一致给出"质疑一次 → 按用户要求交付 → 不再重复质疑"的链条，无需裁决。
- **建议**：按链条合并为一条，保留三段的顺序语义。
- 理由：三份来源在此完全同向，属已收敛项。
