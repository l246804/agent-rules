# 00 · 规则评审台账 schema（Lead 维护，三份台账共用）

**目的。** 把三个来源（P = ponytail、K = andrej-karpathy-skills、H = DeepSeek Harness）的每一条规则/约束逐条过一遍，产出可合并、可裁决的评审台账。**规则写入 `rules/` 是本阶段之后的事：用户确认前不新建、不修改 `rules/`。**

**输入。** 每条规则的逐字引文与出处已在 `findings/01-ponytail.md`、`findings/02-andrej-karpathy-skills.md`、`findings/03-deepseek-harness.md`（已经独立核验并冻结）。台账**不重新取证**，只做判断与改写；出处直接引 findings 的文件行或原始 `path:line`。

**输出。** `review/01-ponytail.md`、`review/02-andrej-karpathy-skills.md`、`review/03-deepseek-harness.md`，条目 ID 沿用 findings 的原始 ID（`P-01`、`R1`、`A1.07`、`B3`、`C2`），保证可回溯。

## 台账头部（每份台账开头必须给）

1. 覆盖范围与条目数（与 findings 的 ID 集合逐一对齐）。
2. 计数摘要：`✅ 推荐` / `⚠️ 条件推荐` / `❌ 不推荐` 各多少条。
3. **最值得收的条目**（≤8 条，一行一条，说明为什么）。
4. **需要用户裁决的条目**（张力、取舍、明显依赖个人偏好；一行一条，写清两难在哪）。

## 条目格式（五字段，顺序固定，字段名逐字一致）

```markdown
### P-01 · 短名（≤8 字）
- 原文：`P:AGENTS.md:7`「逐字英文引文，超长用 … 截断」（同义出处可并列；无逐字引文写「转述」）
- 作用：这条规则改变什么行为、防住什么失败（一句话，不复述引文）
- 是否推荐：✅ 推荐｜⚠️ 条件推荐（条件：…）｜❌ 不推荐（理由：…）
- 使用场景：`base`（+ 一句边界：什么时候不适用）
- 通用化改法：抹掉专名后的**最终规范句**（一句话、正面表述、可判「做到没有」）；已足够通用写「无需改」+ 规范句
- 重复：无重复｜同义（→ 并入 `<ID>`）｜包含或张力（→ 裁决：保留谁、为什么）
```

### `是否推荐` 的判据（必须逐条真判，不许默认 ✅）

- `✅ 推荐`：现代模型**默认不会**这么做（非 no-op）＋ 违反会造成真实损失 ＋ 能判「做到没有」。
- `⚠️ 条件推荐`：只在标注场景成立，条件写在括号里（例如只在多包仓库、只在有发布流程时）。
- `❌ 不推荐`：命中任一条——no-op（模型默认已做）｜不可判定（无法验收）｜纯负向表述且给不出正面目标｜被已过条目完全覆盖且更弱｜只对某一具体产品成立、无法通用化。

## 场景词表（暂定，仅供打标签；最终 `rules/` 目录划分在写作阶段定）

| 标签 | 适用 |
|---|---|
| `base` | 任何技术栈、任何项目形态都成立 |
| `frontend` | 有界面/前端渲染层的项目 |
| `monorepo` | 多包仓库或多人协作 |
| `gates` | 验证与门禁（测试、CI、钩子、脚本化校验） |
| `docs` | 文档、注释与留痕 |
| `agent-cfg` | agent 指令文件/技能自身的写法与分发 |
| `runtime-agent` | 产品内运行时约束（沙箱、审批、日志不变量） |

## 规范句（canonical statement）约定

- 每份台账末尾给 `## 规范句索引（本文件产生）`：一行一条 `- <ID> — <规范句>`，只收**非重复**且推荐/条件推荐的条目；供后一份台账做去重比对。
- 规范句本身：正面表述（写 X，而不是别写 Y）、一句话、可判「做到没有」、**零专名**（不出现框架、库、包管理器、语言、CI 工具、产品名）。
- 一个含义只出现在一个条目里：同义条目只写 `重复：同义（→ 并入 <ID>）`，**不再写规范句**。

## 去重规则（横向比较）

比对范围 = 本来源内部 + 所有**已过**来源的规范句索引（文件在磁盘上，直接读）。三选一：

- `无重复`
- `同义（→ 并入 <ID>）`：含义相同，保留更通用/更可判定的那条。
- `包含或张力（→ 裁决：…）`：一条是另一条的特例（写清谁包含谁），或两条互相拉扯（写清各自成立的条件，给条件化裁决）。

## 覆盖与自检判据（每份台账末尾必须给）

- 覆盖表：findings 里的每个规则 ID 都出现且只出现一次；缺漏逐条写理由。
- 字段完整性：`作用`/`是否推荐`/`使用场景`/`通用化改法`/`重复` 五字段齐全的条目数 == 总条目数。
- 计数：三类推荐计数 + 规范句条数 + 重复分布（无重复/同义/张力）。
- 自检命令：用 grep 数 `^### ` 与五个字段标签的行数，把命令和输出落盘。

## 禁止事项

- 不重新论证已核验的数字（行号、计数以 findings 为准）；发现 findings 有错就走 `send_message` 给 `lead`。
