## 0 元规则

- **R0.1 决策即执行。** 约束要在做出该决策的那一次操作里生效：schema 省略、prompt 过滤、facade、wrapper、监听顺序都不算 enforcement。
- **R0.2 能机械核对的规则就写成脚本。** 副本一致性、生成物同步、引用完整性、格式这类规则交给脚本；其余规则在评审清单里占一个位置。
- **R0.3 规则文件只留一条真在用的。** 每个事实只有一个 home，别处只链接；超预算按 搬迁 → 压缩 → 才抬高上限 处置，抬高要在变更说明里论证。

## 1 动手之前

- **R1.1 读懂再改。** 读任务、读要改的代码、端到端跑一遍真实流程，再选方案；阶梯只缩短解法，不缩短阅读，没读懂的小 diff 是第二个 bug。
- **R1.2 假设写在明处。** 不确定就先问；存在多种解读时全部列出，不静默择一。
- **R1.3 卡住就说清哪里卡住。** 命名困惑点、说明缺什么信息，别猜着往下走。
- **R1.4 高风险先问，其余默认推进。** 删数据、改协议、动安全面、需求自相矛盾先确认；其余取最合理默认值继续做，并在同一次回复里说明"默认了什么、质疑什么"。
- **R1.5 更简方案直说，该推回就推回。** 先交付够用版本，同时说明"已做 X；Y 就够，需要完整 X 请说"；用户坚持要完整版就照做，不再争辩。
- **R1.6 先写可验证目标。** 多步任务先给 `[步骤] → verify: [检查]` 计划；"改好它"这类弱标准必然反复澄清。

## 2 决策阶梯

- **R2.1 写之前先爬梯，命中即停。** ① 需要存在吗（YAGNI）→ ② 本仓库已有？复用 → ③ 标准库？→ ④ 平台原生？→ ⑤ 已装依赖？→ ⑥ 能一行？→ ⑦ 才写最小可用代码。
- **R2.2 只建有人用的东西。** 每个抽象、状态机、选项、防御性拷贝、兼容路径都绑定当前契约或生产消费者；反向气味：只有一个内部调用者的公共方法。
- **R2.3 只建被要求的东西。** 样板、单实现接口、永不变化的配置、给"以后"搭的脚手架，都等到真需要时再写。
- **R2.4 一次性逻辑就近写。** 复用两处以上且语义稳定才提取；页面组件写在路由文件里，不预建目录层。
- **R2.5 同等体量选边界正确的那一个。** 少写代码 ≠ 更脆的算法。
- **R2.6 修根因。** 先 grep 该函数所有调用点，在共享函数里修一次；只修工单点名的那条路径会漏掉同级调用者。

## 3 改动纪律

- **R3.1 改动限于请求范围。** 匹配既有风格；顺手重构、无关格式化不做，需要时在交付说明里提一句。
- **R3.2 每行改动都能追溯到请求。** 根因修复连带改了工单未点名的调用者时，在交付说明里点明。
- **R3.3 只清自己造成的孤儿。** 自己改动导致失效的 import/变量/函数删掉；既有死代码记下来、交给作者决定。
- **R3.4 最短可行 diff 只在读懂之后成立。** 放错位置的小改动是第二个 bug。
- **R3.5 派生文件重新生成，不手改。** 生成物内部（路径、ID、索引）由生成器维护，并在格式化/lint 里排除；是否入库按项目策略。

## 4 类型与信任边界

- **R4.1 相信类型。** 类型已保证的路径直接写，防御代码只出现在真实边界。
- **R4.2 校验只加在真实边界。** parser/config、queued 数据、model/tool JSON、durable/file、worker、process、wire；同进程的类型化边界不加运行时校验与敌意输入测试。
- **R4.3 能推断就不标注。** 第三方边界可做必要收窄；替换 `as`/`as unknown` 时改用有类型值或校验（有基线则保留或减少）。
- **R4.4 判别式用 switch。** 闭合 union 以 `assertNever` 收尾；可扩展 union 落到一个"有文档的 default"。
- **R4.5 错误早且大声。** 配置错误在 load 或最早可解析点失败；空 catch 命名错误与原因，try 只留一条语句。

## 5 依赖与配置

- **R5.1 依赖先爬梯，破例要证据。** 默认 stdlib／原生／已装依赖；新增依赖需要理由：① 维护良好且真正删掉自有代码**与**测试，或 ② 原生方案确实不足；原生不够时它才配得上位置。
- **R5.2 没有未使用的依赖与配置块。** 上游包已完整 re-export 时只声明上游、从同一入口导入。
- **R5.3 只声明与默认值不同的配置。** 部署差异写成显式可校验的配置字段（不是硬编码常量，也不是测试钩子）；协议常量与安全不变量保持固定。
- **R5.4 API 以官方最新文档为准。** 不照抄旧教程；废弃 API 及时迁移。

## 6 测试与验证

- **R6.1 没检查的改动算未完成。** 分支／循环／解析／金钱或安全路径，至少留一个会在该逻辑回归时失败的可运行检查（assert 自检或一个小测试文件，不要框架与 fixture）；平凡一行免测。
- **R6.2 门禁要能被回归弄红。** 断言校验世界而不是自报：从外部重跑命令、重读文件，或断言未触碰的文件逐字节不变。
- **R6.3 测试重量级交给 CI，本地只跑最窄证据。** 覆盖与快照由 CI 守门；本地只跑会因本次回归失败的最窄检查，不重复已通过的检查。
- **R6.4 只报告跑过的命令。** 失败的检查不声称通过，pending 报 pending；被阻塞时原命令不改地重试、申请最窄权限并附证据，绝不绕过测试失败或产品沙箱；绕本地钩子需用户明确同意。
- **R6.5 测试描述行为。** 过时行为连同其测试一起改，并在 PR 里说明原因。
- **R6.6 改完跑本项目的验证入口。** 先确认命令的真实来源（同名内置命令与脚本可能语义不同），再执行。

## 7 沟通与输出

- **R7.1 先给代码，再给最多三行。** 跳过了什么、什么时候该加。
- **R7.2 用户点名的解释给全。** 报告、走查、分阶段笔记不受"最小输出"约束。
- **R7.3 写具体的事实。** 用精确名词陈述契约与上下文，不复述代码、不写推理过程与隐喻。
- **R7.4 更短不等于更好。** 删形容词、重复与叙述，只在每个事实子句都存活且结果更清晰时才算改进。

## 8 留痕

- **R8.1 简化留天花板与升级路径。** 用可 grep 的标记（如 `simplification:`）写明砍掉的能力与升级触发条件；没有升级路径的标记会静默腐烂，定期收割。
- **R8.2 只记录持久的决策理由。** 机械／局部编辑不写记录；记录含"备选方案与它为何落败"；已归档记录冻结；决策反转新写一篇并交叉链接。
- **R8.3 文档与代码同一次改动内同步。** 行为改动更新 README 与注释契约；文档只写当前状态。
- **R8.4 审查只列不改。** 过度工程审查输出发现清单与可削减量（`net: -N lines`）；"最小可运行检查"是下限，不可标为可删。

## 9 流程

- **R9.1 提交历史有意识地规划。** 拆分独立改动；在引入问题的那个 PR 上修；改写历史用 `--force-with-lease`，远端移动即中止，不用裸 `--force`。
- **R9.2 改写后重新取证。** 重新抓远端 head，重新审计评审线程、批准、可合并性与检查；旧 commit hash 与评论锚点不再是证据。
- **R9.3 已发布的世代不可移动。** 预稳定期公开 API 的改动更新每个 consumer；已发布／持久化数据世代只新增版本化后继；持久化类型改动显式致谢并记录。
- **R9.4 安全红线不受最小化影响。** 信任边界校验、防数据丢失的错误处理、安全、无障碍、硬件校准，以及用户明确要求的内容，都保留。
- **R9.5 凭据与不可信输出不进环境。** 子进程用净化 env（丢弃 `*KEY*`／`*SECRET*`／`*TOKEN*`／`*PASSWORD*`）；临时文件用私有目录、随机名、独占打开。

## 10 前端项目追加约定

- **R10.1 路由与全局状态各只有一个入口。** 按项目选型固定路由/状态库，写用其 setState 类 API、读用其 selector 类 API；不使用已废弃 API，不引入第二套路由或状态方案。
- **R10.2 路径别名与相对路径不混用。** 跨目录引用统一用配置提供的别名（如 `tsconfig` paths 的 `@/`），同目录内用相对路径。

## 11 机器管理区块的使用边界

- **R11.1 人工规则不写进机器区间。** 若项目使用会自动改写 `AGENTS.md` 的工具（如 Vite+ 的 `vp config`），其标记区间（如 `<!--VITE PLUS START-->` … `<!--VITE PLUS END-->`）内只放该工具的模板内容，人工规则写在区间之外。
- **R11.2 机器区间不是稳定规则。** 该区间随工具链版本刷新（模板取自工具包自带的 `AGENTS.md`，只覆写标记内部、无标记则完全不写入、永不新建文件），因此不要把其中的文案当项目规则引用或搬进其他文件。
