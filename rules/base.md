# 基础规则

适用于任何项目：动手前通读一遍，之后按所处阶段查阅对应小节。
两个场景文件在本文件之上追加要求：`gates.md` 补充验证与门禁，`frontend.md` 补充界面层。

## 动手之前

- 默认按最小实现与"命中即停"执行；用户明确要求更严格或更宽松时，按其要求执行。
- 该规则集只用于编码与工程任务；提问、翻译、写作等非编码请求不适用。
- 动手前先确认需求是否真的需要存在；投机性需求跳过并一行说明。
- 改动前读完涉及的文件并追出真实调用路径，再动手。
- 改动某个领域前，先读该领域的权威说明，并按其中的约束动手。
- 动手前写下通过/失败可机械判定的判据，且强到无需追问即可独立循环；写不出即说明还没定义清楚。
- 任务有多个独立步骤或有实质风险时，先给简短计划并写明每步的验证方式，再按步执行。
- 目标或方向不确定时指名不清楚之处并先问一句；其余含糊处按写明的假设交付最小可用版本，并在同一回复里说明取舍，不因等待确认而停工。
- 请求存在多种解释时，列出每种解释并说明本次选了哪一种。
- 发现更省的做法就说出并明确一次异议；用户坚持后按原方案交付，不再重复质疑。
- 选定实现路径时，写出被放弃的替代方案与取舍（更省、更快、更稳各在哪一侧）。
- 审查类任务要求显式范围；缺失时报告并停止，不擅自扩大范围。
- 简化提案给少量有实据的候选而非删除计数；调查不构成实施授权。

## 决策与最小实现

- 按成本从低到高依次检查候选方案，取第一个成立的方案并停止比较。
- 只实现刚好满足当前需求的最小版本，不预留扩展点。
- 只创建当前使用点需要的文件与结构，不为未来预留骨架。
- 优先考虑删除或收窄方案，其次才是新增；同一行为用更少的文件与代码行表达。
- 逻辑简单且不损可读时，用一行表达。
- 每个抽象至少有两个使用点且语义稳定；只有一个使用点或语义未定时直接内联实现。
- 交付前量一次改动规模：能减半就先改小；挑出最复杂的一处给出更小的替代，保留原实现时写一行理由。
- 能力接口由定义、实现、使用三方齐备才算完整；只有角色独立演化时才拆分。
- 需要身份或上下文时在编排入口显式恢复并向下捕获，不放宽叶子函数的参数类型来隐藏依赖。
- 一个异步操作只由一个生命周期控制器或事务承载，多余状态要么有独立归属要么合并。
- 服务契约按全部当前消费者设计；只有一个内部调用者的公开方法改为私有实现。
- 每个抽象、状态机、选项与兼容路径都必须绑定当前契约或真实消费者。
- 公开的默认值、操作集与格式都要有当前消费者或既有实践作证；可配置本身不是理由。
- 优先复用仓库里已有的实现与模式，不改写既有同类代码。
- 标准库已有能力时直接用标准库。
- 平台或运行时已内置的能力优先于引入新的依赖。
- 同等成本的两种实现，选边界与异常处理正确的那种。
- 承认两步写入非原子并会在崩溃时重复，用明确顺序与补偿处理，不额外引入状态机。
- 日历型周期规则用显式时刻与时区表达，按日历语义处理缺失与重复时刻。
- 平台提供依赖链或批处理的原生机制时用它，不手工模拟该语义。

## 改动纪律

- 每行改动都要能追溯到请求，否则回退；因本次变更失效的调用点与消费者更新算请求内，与变更无关的相邻代码、注释与格式不动。
- 请求之外的既有死代码只指名提及、不删除，用户明确要求时才清；本次改动造成的未使用导入、变量与函数必须清干净。
- 修缺陷时先查该函数或模块的全部调用点，在共用位置改一次。
- 产品只保留一个受支持的启动入口，其余入口一律拒绝并由检查强制。
- 约束必须在做决定的那一步强制执行，并测试真正的执行者会拒绝被禁止的输入。
- 只在操作成功后发布状态与通知，所有派生视图从同一权威源派生。
- 实验性状态不降低工程、安全、文档与测试要求，只降低对外稳定性承诺。
- 新行为加在文档化的扩展点上；确需改核心时在同一次改动内更新架构文档。
- 同一语义有多个独立投影时，在同一次改动内更新全部投影的期望输出。
- 改写历史时用带租约的强推，远端有新提交即中止；独立改动分开提交并在传播前修源。
- 当一条命令把改写与发布合成一步时，先在它之前确认干净状态、在它之后立即补做验证，命令成功不等于可以交付。
- 新代码沿用所在文件的既有风格；无先例时再按更省的表达选择。

## 类型与边界

- 只在真正的信任边界做运行期校验；类型已保证的取值不再重复校验或兜底；捕获到的异常要么处理要么向上抛出，不静默吞掉。
- 不新增向未知类型的断言；第三方边界可以做必要的类型收窄，但不用断言掩盖真实的类型错误；已有断言只减不增并保持基线。
- 不写多余的显式类型标注或泛型参数，交给类型推断；只在推断不成立或构成公开契约处显式标注。
- 跨边界的不透明标识用带品牌的类型表达，不用裸字符串。
- 对封闭取值集合穷举分支并以不可达分支收口；对可扩展集合保留一个有文档的默认分支。
- 中间件必须显式委派给下一环；不委派即短路，必须是有意为之。
- 边界处的默认值做成显式的解析步骤，不在执行路径里藏隐式兜底。
- 空捕获块写明错误与原因，且其中只放一条语句。
- 平行出现的取值与分支保持对称；不对称必须在原处写明原因。
- 类型定义文件只放类型声明，不放运行时代码。
- 安全边界组件的对外契约（参数、退出码、诊断、失败关闭）保持稳定，不为其他扩展改动。
- 关键能力缺失时表现为不可用或拒绝，绝不静默放宽权限或状态。
- 信任边界的输入一律校验。
- 可能导致数据丢失的路径保留错误处理与恢复手段。
- 安全相关处理保持完整，不因精简而省略。
- 涉及物理设备的项目保留现场校准参数与调整入口。

## 依赖与配置

- 新增依赖前先评估其维护活跃度与社区成熟度，优先选择长期维护、被广泛使用的库。
- 新增或升级外部依赖后，按所装版本查官方文档核对 API 与配置项，不依据旧教程或记忆下笔。
- 只声明与工具默认值不同的配置项；写前先确认该键必需且默认值不满足需求。
- 引入成熟依赖能净减少自有代码与测试时就引入；否则优先用已引入的依赖，几行代码能做的功能不新增依赖。
- 部署间会变的取值做成经校验的配置项；协议常数、外部规格与安全不变量保持写死。
- 配置里引用的外部件必须在依赖清单里声明，并由检查强制。
- 凭据只从运行环境读取，永不写入仓库；缺少凭据的检查自跳过并报告跳过。
- 配置错误在能判定的最早时点大声失败，绝不静默跳过缺失的引用。
- 携带凭据的出站请求禁止跟随重定向，并由测试证明重定向目标未被访问。

## 验证与交付

- 命令因环境限制失败时，先取证再以最小必要权限原样重试；不得靠放宽限制或跳过失败来绕过。
- 静态检查与测试只解析源码平面，构建产物只在显式声明的检查里消费。
- 上限施加在完整产出（含包装与元数据）上，并测试极小值、精确值与单块超限。
- 测试放在包级目录，不内嵌在会被构建或发布的源码目录里。
- 自动修复只处理能确定分类的输入，遇到无法分类的拒绝并报出，不猜测。
- 审查优先报正确性、生命周期与安全类问题，一条有实据的阻断项胜过一串琐碎意见。
- 性能改动跟随实测成本，拒绝不改善真实负载的漂亮改动。

## 沟通与留痕

- 先给可用结果，再用最少的行说明跳过了什么、何时需要补上；用户点名的报告、走查或分阶段说明按其要求完整给出。
- 只报告可复核的计量，不给出无法与真实基线对比的节省数字。
- 注释只写本地需要的信息；不复述代码、不解释远处行为。
- 每个对外导出都写明其非显然契约，函数级导出写明参数与返回值。
- 注释与文档只写完整契约与上下文，不写推理过程与比喻；可机械检查的不变量必须接入顶层门禁，并证明它能拒绝一个无效样例。
- 改动同时更新受影响的文档与注释；每段落一个物理行；一个事实一个归属；文档设有词数上限。
- 机器可读的清单不在文档里人工复述；文档只给出指向真源的链接，确需复述时标注真源位置。
- 每个事实只在一个归属处完整陈述，其余位置只链接。
- 文档只描述当前状态，历史留在提交与决策记录里。
- 每个段落写成一个物理行，靠编辑器软换行。
- 文档中标注语言的代码块必须能编译，逐字粘贴的声明要与源符号核对。
- 多语言配对文档在同一次改动内同步更新并保持结构对应；整篇翻译由用户显式触发。
- 文档超出上限时先在归属层之间搬迁，再压缩，最后才提额并写明理由。
- 按固定清单审查文档：重复规则、越层历史、状态标注、复述清单、推理过程、段落墙与强调膨胀。
- 引用当前文件用相对链接、引用历史用标签或变更编号，不写具体提交标识。
- 把易含糊的术语列为"用前先检查是否够准"的清单，而不是禁用词表。
- 只有在每个事实子句都保留且表达更清楚时才精简；字数变少本身不是改进。
- 删减含事实的段落时，先把每个事实改写成独立成立的陈述，再删掉其余叙述。
- 流程分类字段使用固定的受控集合，每个维度只取一个值。
- 代码里的待办标记只使用受控的少数记号，各自语义固定并写明。
- 有意削减能力而保留已知上限的实现，写一行注释记录上限与升级触发条件。
- 把这类标记汇总成一张台账，每行给出位置、被简化点、上限与升级触发条件；未写明触发条件的单列，标为会静默腐烂的风险项。
- 只对需要长期留存的决策写决策记录，机械改动豁免；写前先搜同主题旧记录，在同一次改动内归档被完整取代者，已归档的冻结不可改。
- 改动对外持久化的数据结构时，在同一次变更内更新该结构的变更记录。
- 报告类任务默认只读；需要写入仓库时先征得同意。
- 会改变对外可见行为的组件，在文档里用固定小节记录其影响与成本。
- 提交的样例数据先归一化：易变标识替换为稳定记号，但不因形似标识符就删任意文本。
- 行为改动在同一次提交更新受影响的文档与注释，并让每个单元声明它归属的权威说明页。
- 长期缺口与维护约束写在固定的"已知限制"小节里，没有也要显式声明。
- 封存产物不可修改，归档时允许的动作被穷举并可校验。
- 封存内容的完整性与元数据由校验强制，任何变更都判失败。
- 已实现的记录随代码同步更新，过时事实在原地改写，不追加变更历史。
- 推翻既有决策要写新记录并交叉链接，不悄悄改写旧记录。
- 归档决定按语义判断，字数与年龄只能用于发现线索，不能作为判据。
- 投影层只放配置与呈现资产，正文与生成物留在归属层，并用门禁防止复制第二棵树。
- 生成物与缓存目录不手工编辑、不提交；要改就改源头。
- 只给清单内的常驻文档设内容上限，缺文件与非法上限都失败；上限向下棘轮，提额必须写明理由。

## 指令文件与分发

- 把工程约束与表达风格约束分开，各自独立生效与开关。
- 写给 agent 的指令要声明行为护栏与范围限制，并说明它是指导还是强制清单。
- 人工指导只承载自动检查覆盖不到的判断，不与门禁重复。
- 会大范围改写产物的批量工作流只由用户显式触发，不由模型自行启动。
- 技能本体只声明名称与描述，触发条件与入口由指令文件的指针声明。
- 向子代理注入上下文时，判定不确定一律注入。
- 环境中已有一份常开规则时，钩子只发一条提示，不再注入第二份。
- 不在宿主会自动加载的约定路径放置不属于该用途的内容。
- 同一规则有多份副本且仓库已有校验设施时，逐字比对全部副本，并为承重条款钉一组必须同时存在的短语；任一漂移即失败。
- 同一内容只维护一个真源，其余入口指向它；宿主适配层只指向主文件，确需副本时副本与主文件逐字一致。
- 需要扩充体量上限时，先压缩再提额并写明理由。

## 多包协作

- 一个扩展点只允许一种导出形态，同类扩展保持一致并由检查强制。
- 可选依赖用显式查询读取，简写形式只留给已声明的必需依赖。
- 所有注册都走框架的效果注册接口并返回注销句柄，保证可回收。
- 新增可插拔单元时一次补齐全部必需注册面，并让漏注册尽早失败。
- 默认安装与发布产物不依赖实验性组件，包含传递依赖与出厂装配，并由检查强制。
- 对外持久化格式只增不改，并保留历史世代。
- 内嵌上游副本保持与上游逐一对应并可追溯；任何本地偏离都登记在同一清单，并随改动重跑该副本的验证。
- 内嵌的上游副本默认排除在审查与改写之外，即使范围为整仓，也不跟随链接进入。
